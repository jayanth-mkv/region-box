## Overview

The user explicitly requested standard shadcn components, simply and quickly. Use the official radix-nova preset with its neutral light theme, generated by the shadcn CLI. This requirement takes precedence over visual concept exploration.

## Colors

Use the generated semantic tokens in src/index.css. A running workspace has a green indicator alongside its text label. Errors include recovery guidance.

## Typography

Use the preset's bundled Geist Variable font and standard Tailwind type scale. Reserve monospace for IP addresses, logs, and paths.

## Layout

A narrow workspace list, a compact toolbar, and a browser stage that receives most of the window. Setup appears inline in standard Card and form components. At narrow widths the workspace list moves above the stage and controls wrap.

First-run onboarding is a dedicated page with a numbered progress list and one active step in a standard Card. Show measured download progress where available and a spinner with the current action otherwise. Preserve progress across restarts, provide retry and defer actions, and make setup available again from Settings. Keep developer paths and file-editing instructions out of credential entry.

## Elevation & Depth

Preserve the standard shadcn component surfaces and borders.

## Shapes

Use shadcn's generated radius scale. Country codes remain easy to scan.

## Components

Use generated Button, Badge, Tabs, Card, Alert, Input, Label, NativeSelect, ScrollArea, Separator, and AlertDialog components. Keep their default styling; only compose layout with Tailwind utilities. Workspace rows show name, country, and status. The browser panel shows Start, Stop, and Check IP.

## Do's and Don'ts

Show actual readiness and verification timestamps. Preserve keyboard focus and loading/error states. Do not create a custom UI system, decorative charts, invented activity, or placeholder connection results.
